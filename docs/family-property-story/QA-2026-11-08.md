## Measured responsive layouts

Every chapter was navigated, captured and measured at each width. No visible main-content element extended outside the document's horizontal bounds.

| Layout | CSS viewport | Document client width | Document scroll width | Horizontal overflow |
| --- | --- | --- | --- | --- |
| Desktop | 1180 × 757 | 1165 | 1165 | 0 px |
| Tablet-width | 834 × 757 | 819 | 819 | 0 px |

The scrollbar accounts for the difference between viewport and client width. Desktop and tablet used a resized Chromium window at 100% zoom. Phone width used that browser at 150% page zoom because its native window has a minimum width. These are real responsive/reflow checks, not native iPhone/iPad, touch or Safari tests.

## Defects found and corrected

1. At 390px in presentation mode, the toolbar squeezed Print into two lines, breaking the word. The toolbar now wraps and keeps button labels unbroken. The final 390px screenshot and geometry verified the correction without horizontal overflow.
2. The source search promised year lookup, but entering 1978 returned zero records because the rendered trust card omitted its year. Filtering now includes the record identifier as well as visible text. Real browser searches for 1978 and 2025 each returned the appropriate single record. Two automated regression assertions cover these cases.
